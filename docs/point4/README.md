# Point 4 — Semantic non-alignment and group discussion topics

This folder documents the fourth research question of **Seeing Inside Telegram Groups**.

## Results and interpretation

- 195 channel–discussion-group pairs (98 crypto; 97 conspiracy).
- Primary analysis: 445,584 semantically eligible group messages, of which 334,080 had maximum cosine similarity below 0.52 to any *observed* associated channel post.
- Mean of pair-level non-alignment rates: **74.68% crypto** and **76.11% conspiracy**, an estimated difference of **+1.43 percentage points** (95% pair-bootstrap interval −3.95 to +6.74; Welch p=0.606).
- Embedding model: `OpenVINO/Qwen3-Embedding-0.6B-int8-ov`; normalized vectors, max sequence length 512, group-query retrieval instruction; similarity = max cosine against observed linked channel posts.
- The matching result measures **semantic non-alignment with observed channel posts**, NOT the independent origin of conversations or proof of novel topics. Corpus size, threshold, channel observation period, message exclusions and duplicates matter.
- Communicative-function/topic results are **exploratory single-pass coding** of a separate pair-stratified 1,170-message sample. The category percentages and bootstrap intervals are conditional on the assigned codes; no independent ground-truth validation of these codes is available. Clusters are topic-discovery diagnostics, not topic-prevalence estimates.

## Reproducibility and private inputs

Run scripts **from the repository root** so that their default `data/interim/point4/` relative paths resolve. Core code requires the original project's Telegram export files, channel/group pair lists and the relevant Python dependencies. Those data and the large embedding `.npy` matrices are deliberately **not** included in this public-facing package. Details are in the supplementary methods and script headers. The scripts represent distinct stages; the full embedding run is expensive and does not need to be repeated to integrate the results.

```powershell
# Existing locally generated data are required. Run from repository root.
python scripts/point4/analyze_point4_full_ready.py
python scripts/point4/point4_methodology.py --analysis-dir data/interim/point4/full_analysis
python scripts/point4/prepare_point4_clustering.py
# The statistical script needs five CSVs in one private local directory:
# pair_policy_summary.csv, topic_policy_summary.csv,
# pair_results.csv, pooled_summary.csv, topic_summary.csv.
# The first two are generated by point4_methodology.py, while the latter three
# come from the full matching run. Copy them together into <statistical_input>.
python scripts/point4/point4_statistical_analysis.py --data-dir <statistical_input> --out-dir data/interim/point4/point4_final_analysis
python scripts/point4/build_point4_stage4_sample.py
python scripts/point4/label_stage4.py
python scripts/point4/analyze_point4_stage4_sample.py --help
```

**Note:** The `refine_point4_taxonomy.py` stage requires the earlier preliminary coding inputs, and the experimental scripts require the local clustering matrices. The qualitative case-review rules are embedded directly in `label_stage4.py`. They do not constitute independent reference labels.
